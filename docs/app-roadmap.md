# Squitle App 后续开发备忘

## 当前决策

项目已经进入网站迁移、macOS App 和可选云同步阶段。网站仍是交互、数据逻辑和视觉设计的基准实现，桌面 App 直接复用同一套页面和核心模块。

云同步采用本地优先模式：不登录时所有功能继续使用本地文档；用户主动开启同步时才注册或登录。第一版只支持同一账号的多设备同步，不提供分享和多人协作。

## 网站稳定阶段的完成条件

- 已知的功能和交互问题已修复。
- Chrome、Safari、Edge 和 Firefox 的核心流程可用。
- 项目、事项、里程碑、依赖连线和 TodoList 的操作逻辑稳定。
- JSON 导入导出和数据版本迁移经过测试。
- 页面刷新、长时间轴、拖动和动画性能达到可接受水平。
- 中英文界面内容完整且含义一致。
- 网站明确标注为试用版，并提示数据保存在当前浏览器。

## App 迁移原则

- App 复用网站已经验证的功能、界面和数据模型，不在迁移时重新设计业务逻辑。
- 网页版与桌面版使用同一种 Squitle 文档格式和同一套数据迁移函数。
- 网站数据通过 JSON 导出并导入 App，不依赖账号或开发者自建云端。
- 用户拥有并管理自己的数据文件。
- App 离线时保持全部核心功能可用。

## App 第一阶段

### 完整功能迁移

- 将稳定的网站功能完整迁移至 macOS App。
- 保持 TimeLine、TodoList、设置、主题、语言和快捷操作一致。
- 建立桌面端回归测试，验证同一份数据在网站与 App 中得到一致结果。

### 本地文档

- 支持新建、打开、保存和另存为 Squitle 文档。
- 默认使用正式 JSON 文档结构，包含 `documentId`、`schemaVersion`、`revision`、`updatedAt` 和 `updatedBy`。
- 使用原子写入，避免写入中断破坏原文件。
- 写入前自动生成 `.bak` 备份。
- 自动保存，并向用户明确显示保存状态和当前文件位置。
- 监听外部文件变化；发现同步冲突时保留双方版本，由用户确认处理，禁止静默覆盖。

### 可选云同步

- 云端采用中国大陆 CloudBase 环境，网站使用平台默认域名。
- 本地 `revision` 与云端 `serverRevision` 分离。
- 上传使用云端版本条件写入，防止多设备静默覆盖。
- 首次连接已有云端数据时由用户选择数据来源。
- 同时发生本地和云端变化时进入冲突状态并保留双方版本。
- 具体协议见 `docs/cloudbase-sync.md`。

## App 更新机制

- GitHub 是源码中心和发布镜像。
- GitHub Actions 自动构建 App，并将安装包同时发布到国内云存储和 GitHub Releases。
- 普通用户下载构建完成的 App，不需要自行编译源码。
- macOS App 使用 Sparkle 检查新版本。
- 检查更新在后台异步进行，失败不影响离线使用。
- 检测到新版本时展示版本号、更新说明和文件大小。
- 用户可以选择“立即更新”“稍后提醒”或“跳过此版本”，不强制更新。
- 更新包必须通过 HTTPS 下载，并校验发布签名和文件完整性。
- 更新失败时保留当前版本和全部用户数据。
- App 默认从国内云存储读取更新清单和安装包，GitHub Releases 作为镜像。

## macOS 发布质量

- 第一批内部测试可以暂时保留系统安全提示。
- 准备正式公开分发时，加入 Apple Developer Program。
- 使用 Developer ID 对 App、DMG 和更新包签名。
- 提交 Apple 公证并装订公证票据，消除常规 Gatekeeper 安全警告。
- 签名、公证和发布流程纳入 GitHub Actions，避免手工发布产生版本差异。

## 后续平台

macOS 版本稳定后，再扩展 Windows 和 Ubuntu。三个平台继续共用：

- 核心业务逻辑；
- Squitle 文档结构；
- 数据版本迁移机制；
- JSON 导入导出；
- 冲突检测和备份语义。

平台差异只保留在文件选择、系统菜单、窗口行为、签名和安装更新层。

## 暂不实施

- 多人协作和项目分享；
- 端到端加密与跨区域数据库；
- Windows、Linux 安装包；
- 强制自动更新。

## 当前实施顺序

1. 固定同步协议与冲突语义；
2. 创建 CloudBase 环境并接入网页登录；
3. 完成网页版多设备同步；
4. 发布到 CloudBase 默认域名；
5. 将同一同步模块接入 macOS App；
6. 配置国内安装包和更新清单。
