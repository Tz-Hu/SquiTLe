# 数据与同步

## 本地优先

Squitle 在未登录状态下即可完整使用。所有修改先形成版本化 `ScheduleDocument` 并写入本地；启用同步只增加远端副本，不改变本地文档的所有权。

一个账号可以保存多个 TimeLine。每个文档使用稳定的 `documentId`，本地修订号和远端修订号相互独立。

## 同步状态机

| 本地变化 | 远端变化 | 结果 |
|---|---|---|
| 无 | 无 | 保持当前状态 |
| 有 | 无 | 条件上传 |
| 无 | 有 | 下载远端版本 |
| 有 | 有 | 按默认数据源处理，或暂停并询问用户 |

首次连接空远端时上传本地文档；发现不同远端文档时，使用设置中的“默认数据源”：每次询问、自动合并、优先云端或优先此设备。任何自动替换都会先在当前浏览器保存恢复副本。上传携带预期远端修订号，服务端只接受匹配的条件写入。

合并以更新时间较新的文档作为同一对象发生冲突时的基准，保留另一端独有的项目、事项、任务轨、依赖和 TodoList 条目。相同任务 ID 视为同一事项；不同 ID 但名称、日期、事项类型、工作类型和备注都一致时也视为重复事项，只保留一份。合并会重映射项目、事项和输出引用，去除重复依赖，并跳过会形成循环的新增依赖。合并前的本地与云端原文档会一起写入浏览器恢复副本。

本地修改保存完成后会防抖上传。前台页面使用轻量修订号检查发现其他设备的更新：Squitle 云端每 5 秒检查一次，WebDAV 每 15 秒检查一次；页面重新获得焦点、恢复可见或网络重新连接时也会立即检查。只有远端修订号变化时才下载完整文档，后台页面不轮询。

## 同步提供方

### Squitle 云端

通过 ChatGPT/Sites 身份确定用户，只同步该用户自己的设备。服务端使用 D1 保存文档和单调递增的远端修订号。

### WebDAV 与坚果云

WebDAV 地址、用户名和应用密码保存在当前设备。浏览器把请求发送到同源代理，再由服务端访问 HTTPS WebDAV 地址，避免把认证头直接发送到第三方页面上下文。

### CloudBase

CloudBase 适配器目前作为可选同步实现保留，不是网站运行的前置条件。公开环境配置来自 `.env`，管理凭据不得进入客户端变量或 Git。

## 备份与迁移

- 文档包含 `schemaVersion`，旧版本通过单向迁移读取。
- JSON 导出用于跨环境迁移和人工备份。
- 同步冲突会保留副本，避免静默覆盖。
